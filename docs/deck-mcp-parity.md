# Deck and MCP parity

Every MCP tool Polaris offers, and how a Stream Deck key reaches it. Generated
from the tool definitions on 2026-10-22; a tool added since is offered
automatically if it changes something and its scope is one a deck key holds.

How a key reaches a tool:

- **`tool.<name>`**: the generic path (`lib/deck/tool-actions.ts`). Every tool
  that changes something, whose scope the deck's key holds, is offered as a key.
  The press goes through `callTool` (`lib/deck/tool-call.ts`): live catalogue,
  the key's scope, the tool's own schema, its MCP budget and the audit - the
  same gates `/api/mcp` applies. Fields are read from the tool's input schema;
  `deviceId`, `routineId`, `conversationId`, `calendarId` and `sessionId` are
  pickers of the person's own. A tool whose required input is a list or an
  object is left out at runtime (nothing a settings screen can fill).
- **Asks for a second press**: every tool not marked `destructive: false`. The
  plugin arms the key ("Again?") and runs it on a second press within 2 s.
  Companion has no second press and leaves these out.
- **Dedicated**: hand-made actions with their own state, dial or picker.
- **Off the deck**: mail, the databases, Drive's share links and the cameras.
  A deck key is never granted those scopes (`lib/deck/scopes.ts`).
- Read-only tools have nothing to press; the state keys cover what a key can
  show.

Labels of `tool.*` keys are the tool's English title: MCP tools are named for
the model and have no translations.

## Keys with no MCP tool

The call keys work the call the person is on, in the browser tab that holds
it (`lib/deck/call-actions.ts`, `lib/chat/call-remote-service.ts`). The
microphone, camera and recorder are that tab's, so there is no tool an
assistant could call for them: a press finds the person's own admitted seat
and asks that tab on the call's stream, and the key reads back what the tab
last said on its seat. Out of a call, every key shows "No call" and a press is
refused with "You are not in a call right now." Scope `chat.use`; on Companion
each is an action, a feedback and a variable, and the toggles also an "is on"
feedback.

| Key           | Kind   | Scope    | Deck                                                                                                           |
| ------------- | ------ | -------- | -------------------------------------------------------------------------------------------------------------- |
| `call.mic`    | toggle | chat.use | [x] dedicated: lit and crossed out while muted                                                                 |
| `call.deafen` | toggle | chat.use | [x] dedicated: lit while deafened                                                                              |
| `call.camera` | toggle | chat.use | [x] dedicated: on or off, as the tab reports it                                                                |
| `call.record` | toggle | chat.use | [x] dedicated: the call screen's rule - the host, or anybody in a direct message or a group; refused otherwise |
| `call.hangup` | run    | chat.use | [x] dedicated: leaves the call in the tab that is on it                                                        |
| `call.sound`  | run    | chat.use | [x] dedicated: plays a picked sound through the soundboard's own checks                                        |

## Places devices on the deck

Every kind of device Places has (`apps/places/src/lib/device-kinds.ts`), and
the keys that work it. Pickers read `places_devices`, which lists each
device's actions by their spoken names (`open` is the panel's Open button),
and only devices this person may work. Places has no blinds, vacuums or
camera movement: a cover, a robot or a PTZ preset is nothing a device here
can be. The cameras' scope stays off the deck.

| Kind      | What it does                                                        | Keys                                                                                              |
| --------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| lock      | lock, unlock, open (unlatch)                                        | places.door, places.device (opens), places.device-command                                         |
| opener    | open                                                                | places.door (open), places.device (opens), places.device-command                                  |
| light     | on/off, brightness, warmth, colour                                  | places.device-toggle, places.device, places.brightness (dial), places.light-white, places.light-color |
| switch    | on/off                                                              | places.device-toggle, places.device, places.device-command                                        |
| outlet    | on/off                                                              | places.device-toggle, places.device, places.device-command                                        |
| climate   | on/off, temperature, mode, fan, options                             | places.climate (dial), places.temperature-step, places.temperature-set, places.device-setting, places.device-toggle |
| air       | on/off, mode, fan, humidity, options                                | places.device-toggle, places.device-setting; humidity and options through tool.places_device_control |
| appliance | stop                                                                | places.device-command (stop)                                                                      |
| litter    | clean, pause, resume, (dump, deodorizer reset, options)             | places.device-command; dump stays off a key, the rest through tool.places_device_control          |

| routines  | run                                                                 | places.routine-run (home.manage)                                                                  |

Why a door could not be worked before: `places.door` listed only devices
that take `lock`, so an opener (a building door, which takes only `open`)
never appeared in its picker.

A press shows its result at once. Each Places state carries `press`: the face
a press shows while the command is on its way ("Locking", the switch flipped,
the new set point) or `noop` when the device already is there, in which case
neither the plugin nor Polaris sends anything. The plugin and Companion put
the previous face back, with the alert, when Polaris refuses or does not
answer in 15 s; a dial's ticks move its face and land as one command, and a
burst that ends where it began sends nothing.

A deck whose key lacks a permission its owner holds - connected before it was
offered, or approved with it unticked - is told so: the catalogue lists those
actions under `locked`, the settings screen says "Reconnect this deck to
allow: ...", a key set to one draws "Reconnect", and a press is refused in
the same words. A visitor who was lent a door holds no `home.control`, and
the device tool's scope stands on it, so a deck cannot work a lent device;
the Places screen can.

## Calendar timers on the deck

`calendar.timer` (`apps/calendar/src/lib/deck-actions.ts`, scope
`calendar.manage`) works one of the account's Calendar timers, a new one found
by its name and made on its first press, or the focus cycle - through the clock
tools above, so a deck reaches exactly the timers its owner does. Its state
carries `countdown`: what is left, the length, and while it runs when it ends
and the server's clock, so a Stream Deck key or a Companion button counts down
between readings to the same second as Calendar. A change made anywhere - the
Time screen, a tool, another deck, the timer ringing - is announced on the deck
bus (`lib/deck/live.ts`) and reaches open decks within a second.

On a Stream Deck the timer key's Source picks this or a timer kept in the
plugin (the default, and every key set before). In Companion the Timer action
and feedbacks do the same, kept on that machine or in Polaris.
